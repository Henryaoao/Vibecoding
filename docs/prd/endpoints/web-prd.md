# ProjectM Web 端 PRD

## 1. 文档状态

- 端侧：Web。
- 状态：生效。
- 范围：Web 端技术栈、浏览器信息架构、页面结构边界、Web Admin Console 和实现约束。
- 继承：整体项目 PRD、权限参考和 OMX 决策策略。

## 2. Web 端目标

Web 端为员工提供桌面浏览器中的 ProjectM 门户，并为 `super_user` 提供受保护的 Web Admin Console。Web 端既承担员工信息入口，也承担当前 MVP 的全部管理写入入口。

## 3. Web 技术栈

当前接受的 Web 技术栈是：

- React
- TypeScript
- Vite

改变该技术基线需要先向用户说明原因并获得确认。

## 4. Web 信息架构

| 区域 | 目的 | 角色 |
| --- | --- | --- |
| 登录与会话状态 | 登录、退出、会话过期、无权限提示。 | `user`、`super_user` |
| 员工门户首页 | 聚合七个 MVP 模块的入口和摘要。 | `user`、`super_user` |
| 模块页面 | 七个 MVP 模块的列表、详情、筛选和允许的互动。 | `user`、`super_user` |
| 个人/任务区域 | 展示个人新人任务、培训进度等本人数据。 | `user`、`super_user` |
| Web Admin Console | 内容、文档、课程、新人、用户、角色、首页配置和审计管理。 | `super_user` |

## 5. Web 页面结构边界

Web 可以在阶段 PRD 中细化页面结构，但整体约束如下：

- 员工门户可以包含首页、模块列表页、模块详情页、搜索/筛选状态、空状态和错误状态。
- Web Admin Console 可以包含仪表盘、内容管理、文档管理、培训管理、新人管理、用户与角色管理、分类/标签管理、首页配置和审计查看。
- 页面结构可以写入端侧或阶段 PRD；具体 UI 文案、视觉样式和组件实现不应写入整体项目 PRD。
- Web 路由保护只是体验层，后端授权仍是安全事实来源。

## 6. Web 交互规则

- Web 必须消费后端 API 合同，不得自行定义权限事实来源。
- `user` 不应看到 Admin Console 入口；即使手动访问，后端也必须拒绝管理 API。
- `super_user` 可进入 Web Admin Console，但所有写入仍必须由后端校验。
- Web 必须明确处理未登录、会话过期、无权限、空数据、加载、错误和重试状态。
- Web 不得实现浏览历史、最近浏览或被动页面访问轨迹。
- 财经轻资讯页面必须保持非投资建议边界。

## 7. Web Admin Console 范围

Web Admin Console 的 MVP 管理范围包括：

1. 今日公司简报管理。
2. 公司公告管理。
3. 员工论坛热帖治理。
4. 新人资料和任务模板管理。
5. 财经轻资讯内容管理与合规提示。
6. 文档上传、授权、发布、归档和下线。
7. 培训课程、材料和状态管理。
8. 用户管理与 `user` / `super_user` 角色分配。
9. 首页配置、分类/标签管理和审计查看。

## 8. Web 范围外

- App 移动端导航、平台状态和离线体验。
- 数据库字段清单、迁移 SQL 和后端实现代码。
- 生产部署细节和真实密钥。
- 完整测试用例和 QA 自动化脚本。
- 任何第三种应用角色。

## 9. OMX 交接提示

执行 Web 实现前，先读取整体 PRD、Web 端 PRD、权限参考、API 合同基础 PRD、Web 壳层 PRD，以及对应模块的后端 PRD 和 Web 前端 PRD。若 Web 页面需要新增或调整后端合同，必须更新模块合同登记表。
