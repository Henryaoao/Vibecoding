# ProjectM App 端 PRD

## 1. 文档状态

- 端侧：跨平台 App。
- 状态：生效。
- 范围：App 端技术栈、移动端信息架构、导航、交互、平台状态和实现约束。
- 继承：整体项目 PRD、权限参考和 OMX 决策策略。

## 2. App 端目标

App 为员工提供移动端 ProjectM 信息入口。`user` 与 `super_user` 都可以在 App 中作为员工门户用户访问自己有权限的内容；App 不承载移动端管理写入。

## 3. App 技术栈

当前接受的 App 技术栈是：

- React Native
- TypeScript
- Expo-managed workflow

推荐该技术栈的原因是它能保持 TypeScript 技能复用，并降低跨平台移动端交付成本。改变 React Native + TypeScript + Expo 技术基线需要向用户说明原因并获得确认。

## 4. App 信息架构

App 信息架构应移动优先、任务优先：

| 区域 | 目的 | 角色 |
| --- | --- | --- |
| 登录与会话状态 | 登录、退出、会话过期、无权限提示。 | `user`、`super_user` |
| 首页/摘要 | 聚合今日简报、公告、热帖和关键入口。 | `user`、`super_user` |
| 内容列表与详情 | 阅读公告、热帖、财经资讯、文档元数据和培训内容。 | `user`、`super_user` |
| 我的任务/进度 | 新人任务和培训进度的本人状态。 | `user`、`super_user` |
| 我的/设置 | 账户信息、会话、缓存/网络提示和基础设置。 | `user`、`super_user` |

## 5. App 导航建议

阶段 PRD 可以进一步细化导航。默认建议：

- 底部 Tab 或等价移动端主导航承载首页、内容/模块、文档/培训、我的。
- 模块详情使用移动端栈导航。
- 搜索、筛选、排序使用适合移动端的交互模式。
- 离线、弱网、重试和空状态必须在每个模块执行前明确。

## 6. App 交互规则

- App 必须消费后端合同，不得定义 API 事实来源。
- App 必须在阶段 PRD 中明确离线或弱网状态。
- App 不得在未确认的安全策略外缓存敏感文档。
- App 不得引入被动页面浏览历史、最近浏览或访问轨迹。
- App 中的财经轻资讯必须保留非投资建议边界。
- App 必须用移动端合适方式展示 401、403、会话过期、空状态、错误和重试。
- 个人进度和新人任务更新只能影响当前认证用户自己的记录，除非未来用户确认新的移动端管理范围。

## 7. App 管理边界

ProjectM 有面向 `super_user` 的受保护管理能力，但 App 当前不包含移动端 Admin Console 或管理写入工作流。所有 `super_user` 管理工作，包括内容管理、用户管理、角色分配、首页配置和审计查看，均由 Web Admin Console 承担。

如果未来提出移动端管理写入，必须先创建新的 App 管理范围提案并向用户确认，因为这会改变端侧范围和安全面。

## 8. App 范围外

- 移动端管理写入、移动端 Admin Console、用户管理和角色分配。
- 数据库 schema 或后端 API 的事实来源。
- 生产部署细节、商店发布流程和真实密钥。
- 完整测试用例和自动化脚本。
- 任何第三种应用角色。

## 9. OMX 交接提示

执行 App 实现前，使用 React Native + TypeScript + Expo-managed workflow 作为技术基线，并读取 App 壳层 PRD、对应模块后端 PRD 和 App 前端 PRD。除非未来用户明确改变边界，所有管理写入都不进入 App 范围。
