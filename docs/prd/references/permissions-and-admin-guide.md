# ProjectM 权限与 Admin 指南

## 1. 目的

本文负责说明 ProjectM 的角色行为、权限边界和 Web Admin Console 使用规则。它继承整体项目 PRD，不得引入额外应用角色。

## 2. 角色定义

| 角色代码 | 名称 | 用途 |
| --- | --- | --- |
| `user` | 普通员工 | 使用 Web/App 员工门户，访问自己有权限的内容和个人任务/进度。 |
| `super_user` | 超级用户 | 使用 Web/App 员工门户，并通过 Web Admin Console 管理内容、文档、课程、新人材料、用户、角色、首页配置和审计可见性。 |

## 3. 通用权限原则

- 后端授权必须保护所有受限 API。
- 前端隐藏入口只提升体验，不构成安全边界。
- `/api/v1/admin/*` 必须要求 `super_user`。
- 角色分配只能在 `user` 与 `super_user` 之间进行。
- 管理写入需要记录操作者、时间和业务对象，但不得记录密钥或敏感正文载荷。
- 操作者归因统一记录认证后的 ProjectM 内部 `users.user_id`，建议审计字段名为 `actor_user_id`；基于 Teams 登录的外部身份辨别使用 `teams_tenant_id` + `teams_user_id`，不得用邮箱、显示名或前端传入值作为审计主键。
- 所有用户发起写入都由后端从 session 归因，字段名按业务语义选择：作者/创建者使用 `author_user_id` 或 `created_by_user_id`，个人所属记录使用 `user_id`，更新者使用 `updated_by_user_id`，执行者/审计使用 `actor_user_id`。前端不得提交这些字段来声明操作者。
- App 不承载移动端管理写入。

## 4. 能力矩阵

| 能力 | `user` | `super_user` |
| --- | --- | --- |
| 员工门户访问 | 可以访问有权限内容。 | 可以访问有权限内容。 |
| 今日公司简报读取 | 可以。 | 可以。 |
| 公告读取 | 可以。 | 可以。 |
| 热帖读取/轻量互动 | 可以，受后端合同限制。 | 可以，受后端合同限制。 |
| 新人个人任务 | 只能更新自己的任务状态。 | 只能在员工门户中更新自己的任务状态；模板管理在 Web Admin Console。 |
| 财经轻资讯读取 | 可以，必须看到非投资建议边界。 | 可以，必须看到非投资建议边界。 |
| 文档访问 | 只能访问授权文档。 | 可访问授权文档；授权管理在 Web Admin Console。 |
| 培训个人进度 | 只能更新自己的进度。 | 只能在员工门户中更新自己的进度；课程管理在 Web Admin Console。 |
| Admin Console | 不可访问。 | 仅 Web 端可访问。 |
| 管理 API | 不可调用。 | 可在后端授权通过后调用。 |

## 5. Web Admin Console 区域

| 管理区域 | 建议路由族 | 能力 |
| --- | --- | --- |
| 管理首页 | `/admin` | 查看概览、待处理事项和运营入口。 |
| 简报管理 | `/admin/briefings` | 创建、编辑、排期、发布、置顶、归档和下线简报。 |
| 公告管理 | `/admin/announcements` | 管理公告、置顶、有效期和状态。 |
| 热帖治理 | `/admin/forum` | 管理帖子可见性、状态、排序和违规处理。 |
| 新人管理 | `/admin/newcomer` | 管理资料、任务模板、排序和状态。 |
| 财经资讯管理 | `/admin/finance` | 管理财经内容、免责声明、合规提示和状态。 |
| 文档管理 | `/admin/documents` | 上传、授权、发布、归档、下线和版本管理。 |
| 培训管理 | `/admin/training` | 管理课程、材料、排序和状态。 |
| 用户管理 | `/admin/users` | 查看用户、调整角色、停用或恢复账户。 |
| 角色参考 | `/admin/roles` | 展示并分配 `user` 或 `super_user`。 |
| 首页配置 | `/admin/home` | 配置门户首页模块顺序和推荐内容。 |
| 审计查看 | `/admin/audit` | 查看管理写入审计和安全相关事件。 |

## 6. 登录与 Admin 入口流程

1. 用户登录后，后端返回当前用户身份和角色声明。
2. Web 员工门户按角色展示可用入口。
3. 如果用户是 `super_user`，Web 可以展示 Admin Console 入口。
4. Admin 页面仍调用需要 `super_user` 的后端管理 API。
5. 如果 API 返回 401、403 或会话过期，Web 必须回到统一认证/权限处理。

## 7. App 权限行为

- App 使用同一认证和后端合同。
- App 不展示移动端 Admin Console。
- App 不提供内容管理、用户管理、角色分配、首页配置或审计写入。
- `super_user` 在 App 中按员工门户用户使用相关模块。
- 个人任务和个人进度更新只能影响当前认证用户自己的记录。

## 8. 模块管理规则

- 所有模块的管理写入均走后端管理 API，并要求 `super_user`。
- 员工读取接口只返回当前用户有权访问的内容。
- 管理端发布、归档、下线等生命周期动作必须由后端校验状态转换是否合法。
- 财经轻资讯管理必须保持非投资建议边界。
- 文档授权必须由后端判断，不能依赖前端筛选。

## 9. 验收要求

- 项目只出现 `user` 和 `super_user` 两种应用角色。
- `user` 无法访问 Admin Console 或管理 API。
- `super_user` 管理写入有后端授权和审计。
- App 不包含管理写入。
- 财经轻资讯不出现股票推荐、买卖建议、个股预测或收益承诺。
