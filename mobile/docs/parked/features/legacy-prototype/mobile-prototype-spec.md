# ProjectM 移动端原型说明

## 1. 文档目的

本文档记录 ProjectM Mobile 第一轮中低保真原型的设计范围、信息架构、页面清单、关键流程和评审标准。

原型目标是在创建 RN + Expo 工程前验证：

- 移动端首页信息密度是否合理。
- 7 个用户模块是否都有清晰入口。
- `user` / `super_user` 权限状态是否清晰。
- 移动端 Admin Console 是否适合手机操作。
- 推送通知、文件预览、403、空状态和错误状态是否可被用户理解。

本轮原型不改变 PRD 需求，不代表最终视觉设计。

## 3. 信息架构

### 3.1 普通用户 Tab

```text

└── User Portal
    ├── 首页
    ├── 文档
```

```text
    ├── 文档管理
    ├── 课程管理
    ├── 新人任务管理
    ├── 分类标签
    ├── 用户角色
```

## 5. 可点击流程

### 5.1 普通用户主流程

1. 登录页选择普通用户登录。
2. 进入首页。
3. 查看今日公司简报。
4. 进入文档中心。
5. 打开文档详情。
6. 进入文件预览。
7. 查看预览失败降级入口。
8. 进入培训中心。
9. 进入个人中心。
10. 查看通知偏好。

### 5.2 Super User 管理流程

1. 登录页选择超级用户登录。
2. 首页显示 Admin Console 入口。
3. 进入 Admin Dashboard。
4. 进入内容管理列表。
5. 打开内容详情。
6. 进入编辑页。
7. 点击发布。
8. 查看二次确认。
9. 查看发布成功状态。

### 5.3 权限流程

1. 普通用户登录。
2. 通过原型中的“模拟访问 Admin”进入 Admin 路径。
3. 展示 403 页面。
4. 返回首页。

## 6. 状态覆盖

原型覆盖以下状态：

- loading：列表页和详情页的加载占位。
- empty：列表筛选无结果。
- error：网络或预览失败。
- forbidden：普通用户访问 Admin 的 403。
- confirm：发布、归档、软删除二次确认。
- permission denied：文档预览无权限说明。

## 7. 评审标准

### 7.1 PRD 覆盖

- 7 个用户模块都有入口。
- 首页第一屏突出今日公司简报。
- 个人中心包含收藏、下载、培训进度、新人任务和通知偏好。
- Admin Console 有核心模块入口。
- 内容管理有完整单条流程。
- 财经详情有免责声明。

### 7.2 权限

- `user` 不显示 Admin 入口。
- `user` 模拟访问 Admin 时显示 403。
- `super_user` 显示 Admin 入口。
- Admin 操作有二次确认。

### 7.3 可用性

- 首页信息不过载。
- 文档预览失败有降级入口。
- 推送权限被拒绝不阻断主流程。
- Admin 表单适合手机操作。
- 列表、详情、编辑和确认之间路径清晰。

## 8. 后续处理规则

- 如果评审发现需求缺口，先向用户确认 PRD 修改范围，再更新 `docs/prd/` 当前事实来源，并在 `mobile/docs/mobile-project-status.md` 记录原因。
- 如果评审发现技术方案需要调整，更新 `mobile/docs/mobile-architecture.md`，并在 status 中记录具体改动和原因。
- 如果只是原型问题，更新本文件和 `mobile/prototype/index.html`，并同步 status。
