# Output Template

## Route

- work unit identifier
- selected primary route
- selected secondary routes
- standards family
- why the routing is correct

## Rule Stack

- shared QA files applied
- route packs applied
- high-risk layering reference applied, if relevant
- HTML report template reference applied, if relevant
- local project report template path, if relevant
- active coverage layer, if relevant
- credential provider and local-prompt protocol, if credentialed access is used
- whether methodology provenance or official-doc reading was used

## Conclusion

- main deliverable summary
- readiness or risk concentration

## Findings Or Design Output

- risk, requirement, issue, or implementation change
- impact
- evidence label

## Failure Ownership Or Automation Feasibility

- ownership category or feasibility boundary
- why that call is justified

## Validation

- command, artifact path, report path, or exact blocked reason
- what was not validated yet
- for manager-style work: current module, current gate, status distribution,
  report archive, and next decisive action
- for credentialed website access: no-secret preflight result, local prompt
  boundary, redacted discovery artifact, and secret scan result
- for HTML reports: archive path, latest mirror, expected pages, rendered case
  rows versus approved denominator, screenshot policy, postcheck, and secret
  scan result

## Residual Risk

- what remains unresolved
- what should be verified next

## Post-Task Evolution Gate

- work-unit closeout completed: yes or no
- task class
- reusable learning: yes or no
- selected target layer: common, route-specific, or both
- next action: no change / log only / candidate / promote / release

## Evolution Conclusion

- generalized principle or explicit `no change`
- whether the learning is route-specific or cross-route
- whether Loop 2 found a weakness in the evolution process itself
